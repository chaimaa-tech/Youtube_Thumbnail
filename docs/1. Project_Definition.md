
# Project Definition

---

## 1. Project title

**Do Thumbnails Predict Video Performance?** A data engineering pipeline and prediction model on YouTube cooking channels.

## 2. Context

Creators spend a lot of effort designing thumbnails (bright colors, bold text, expressive faces) because they believe thumbnails drive clicks. This project tests whether that belief shows up in real data.

It is also a portfolio project meant to add two things my first project (MyMelody, a Spotify ETL + dashboard) did not cover:

- a **data science layer** built on a pretrained model (transfer learning),
- **unstructured data** (images).

## 3. Problem statement

Given a video's metadata and its thumbnail, can we predict how many views it will get, and does the thumbnail add predictive value beyond the metadata alone?

## 4. Objectives

| #  | Objective                                                                            |
| -- | ------------------------------------------------------------------------------------ |
| O1 | Build a reproducible pipeline from the YouTube Data API to analysis-ready tables     |
| O2 | Handle two data types: structured metadata (JSON) and unstructured images (.jpg)     |
| O3 | Convert thumbnails into numeric features using a pretrained image model (embeddings) |
| O4 | Train a simple, explainable model to predict view count                              |
| O5 | Measure whether thumbnail features improve predictions over a metadata-only baseline |
| O6 | Present results in a dashboard                                                       |

## 5. Success criteria

**Technical**

- The pipeline runs end to end from raw API data to the final table without manual fixes.
- Raw data is stored untouched, so nothing requires re-calling the API.
- Two models are compared: **baseline (metadata only)** vs. **metadata + thumbnail features**, evaluated on held-out data.

**Project**

- Every step is documented and explainable.
- A working demo exists (dashboard).

**Not a success criterion:** high accuracy. With a few hundred videos, an honest comparison and a working pipeline matter more than a perfect predictor. A result of "thumbnails add little" is still a valid finding.

## 6. Scope

**In scope**

- One niche: cooking
- 8 channels, about 50 recent videos each (~400 videos)
- Metadata: title, publish date, views, likes, comments, subscriber count
- Thumbnail images (high resolution version)
- Pretrained ResNet50 embeddings and a RandomForest regressor
- Dashboard of results

**Out of scope**

- Training an image model from scratch
- Other niches or platforms
- Real-time or streaming data
- Video content, audio or transcript analysis
- Production deployment

## 7. Data source

| Source                                                                    | Format | Access                    |
| ------------------------------------------------------------------------- | ------ | ------------------------- |
| YouTube Data API v3 (`search.list`, `videos.list`, `channels.list`) | JSON   | API key stored in`.env` |
| Thumbnail URLs from the metadata                                          | .jpg   | Direct HTTP download      |

Chosen channels: Joshua Weissman, Binging with Babish, Adam Ragusea, Bon Appétit, Sorted Food, Emmymade, You Suck at Cooking, Pro Home Cooks. They were picked to cover varied thumbnail styles and audience sizes.

## 8. Constraints and risks

| Risk / constraint                                             | Impact                                  | Mitigation                                                            |
| ------------------------------------------------------------- | --------------------------------------- | --------------------------------------------------------------------- |
| API daily quota (10,000 units;`search.list` = 100 per call) | Blocks extraction                       | Small, deliberate scope; save raw JSON and avoid re-calling           |
| Small dataset (~400 videos)                                   | Overfitting, weak signal                | Simple model, PCA on embeddings, honest evaluation                    |
| Channel size dominates views                                  | Model learns "big channel = more views" | Predict log(views) and/or normalize by channel size; split by channel |
| Video age affects views                                       | Older videos have more views            | Include`days_since_published` as a feature                          |
| Shorts and livestreams mixed in                               | Distorted view counts                   | Decide a filtering rule at extraction                                 |
| View counts change over time                                  | Results depend on extraction date       | Record the extraction date                                            |

## 9. Data engineering layers

| Layer                            | Content                                                    | Tools (planned)                    |
| -------------------------------- | ---------------------------------------------------------- | ---------------------------------- |
| **Bronze (raw)**           | Raw API JSON, downloaded thumbnails                        | Python, files in`data/raw/`      |
| **Silver (clean)**         | `dim_channel`, `dim_video`, `fact_video_performance` | pandas, SQLite/Postgres or Parquet |
| **Gold (analytics-ready)** | One row per video: metadata features + embeddings + target | pandas, ResNet50                   |
| **Serving**                | Model results and dashboard                                | scikit-learn, Streamlit            |
